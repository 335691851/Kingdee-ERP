# 物料分类与关联数据升级

依据用户新增的分类照片，主数据改为两级分类，并将原表“其中”拆为独立统计维度。

| 一级分类 | 二级品种 |
|---|---|
| 食用盐 | 食品加工用盐、小包装 |
| 非食用盐 | 精工饲料盐、散湿盐、海盐散原盐、药用盐、软水剂 |

“精工饲料盐”按图片可识别文字保留。辅助原料和包材另设“辅助物料 → 原料 / 包材”，不计入产销盐品合计。另保留“非食用盐 → 品种待确认”承接原有工业精制盐，因为附件未证明它属于散湿盐或饲料盐，不能强行归类。

## 映射与属性

- 原食用精制盐、海藻盐、调味盐、低钠盐共 6 项归入“食用盐 → 小包装”。低钠、调味等原信息保留为产品特征。
- 原药品氯化钠归入“非食用盐 → 药用盐”；工业精制盐保留待确认状态。
- 补充食品加工用盐、精工饲料盐、散湿盐、海盐散原盐、软水剂 5 项示例产品，编码均以 DEMO 开头并在名称标“模拟新增”。不是新增企业真实物料的声明。
- 盐源为海盐 / 矿盐 / 来源待确认 / 不适用；包装为小包 / 大包 / 散装 / 不适用。“400g 小包装入 20kg 外袋”仍属于小包，不因运输外包装为 20kg 改为大包。
- 未据品牌、生产公司、海藻风味推定海盐或矿盐。新增海盐原盐示例有独立的模拟海盐粗盐来源，其余未知来源继续待确认。因此矿盐筛选可能为空，这不等同于真实企业没有矿盐业务。

最终有 27 项物料：13 项产销盐品和 14 项辅助物料；13 个分类节点包括 3 个一级、10 个二级。原有 10 项物料的 ID 和编码保留，新物料另行编码。所有业务仍通过同一物料 ID 引用主数据，库存、成本和利润展示一级 / 二级分类，利润可按分类、盐源、包装筛选并汇总。

## 业务合理性

1. 包装 BOM 按规格区分：25kg 为 40 袋/吨，50kg 为 20 袋/吨，1000kg 为 1 个吨包/吨；20kg 外袋为 50 袋/吨，19.2kg 外箱约为 52.083333 件/吨。
2. 小包装另计内包装：400g 为 2500 袋/吨，500g 为 2000 袋/吨，320g 为 3125 袋/吨。海藻、调味和低钠产品另有模拟配方原料；低钠示例包含氯化钾，海藻产品包含预混料。**这些是演示耗用假设，未采用企业真实配方，也不作为生产、质量或工艺标准。**
3. 散湿盐、海盐散原盐采用散装示例，不消耗包装材料。海盐散原盐使用独立海盐粗盐示例原料；原料与产成品身份区分，避免重复统计。
4. 每类产品从 BOM 推导采购与领料数量，再根据实际领料金额计算生产成本、完工成本、内部交易价格、库存余额和销售毛利。金额、税额、收付款核销、库存与凭证同步生成；没有只改名称而保留不匹配的领料记录。
5. 所有模块仍保留 30 万张核心单据，20 类单据各不少于 1 万张；图片的 7 个品种都有模拟销售、采购与生产记录。分类汇总和产品明细利润严格勾稽；海盐/矿盐及包装交叉统计不与主分类合计相加。
6. 示例售价不因毛利为负而自动修改；损益由模拟售价、材料和分摊成本计算，亏损不作为金额不平衡。它不代表真实企业或真实产品盈利水平。

## 升级、回退与交付

本地原库经检查仅包含初始模拟历史、没有新增人工单据，已先备份到 `work/backups/20261104-taxonomy/erp-v1.db`，旧版源码包与数据包也在同目录。新历史先在独立数据库中生成、校验，再切换预览。因增加了明细和包材，明细/库存事务条数会变化，但核心单据数与各模块万行要求保持。

本次重建了模拟历史，历史单据明细、BOM、成本和利润会随新参数更新。正式业务库不能采用这种重建方式，应另行编写可审计迁移并保留已结账历史。旧版下载用户应配套使用新版代码与新版数据，不能仅替换代码并继续使用旧结构数据库。Supabase 当前仍未连接或写入；schema.sql 适用于空的新库。
