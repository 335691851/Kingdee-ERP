## 应用验证

生产 `/api/health` 返回 `status=ok`、`database=postgresql`、`auth_mode=supabase`、`data=simulated`。首页、两个 JavaScript 文件及样式均返回 200，线上脚本内容与本地源文件一致（仅 Git 换行格式差异）。未登录 `/api/me` 返回 401。

生产首页由服务端清空演示账户和密码并显示 Supabase 邮箱提示。最新本地检查 17 项通过。后续环境配置曾将第一个 TLS 查询参数写为 `&sslmode=require`，导致库名误识别；应用已对共享池的这一明确笔误作兼容修正，保留密码、主机名与其它设置。

## 首次使用账户

截至验收，Supabase Auth 用户数为 0，因此尚未完成真实管理员登录后的云端业务操作验收。请先在 Supabase Authentication → Users 创建并确认实际邮箱用户，再按《生产环境配置.md》将该用户 UUID 授予 ERP 法人权限。生产环境不接受本地演示密码。

数据库连接密码只保存在 Vercel 敏感环境变量内，未写入代码、文档或仓库。环境变量配置见同目录 environment.production.example 和生产环境配置.md。
