## 来源与计算

public.ai_restock_plan_input 严格输出 12 列，security_invoker=true。ai_restock_source 保存可维护的快照、计划窗口、需求预留、模拟安全库存批准与剩余产能依据；订单净需求来自 document_line＋delivery_schedule，可用库存来自 stock_balance。在途来自同公司SKU的 SIM-AIP-Rxx-TR 采购订单及交付计划；已排产来自 SIM-AIP-Rxx-MO 生产单及 production_detail。取消/非确认状态、窗口外到货/完工不计入。采购链 demand 不作为销售需求。

R06 未交100吨减本需求预留60吨，demand_qty=40；实物80减占用60，available_qty=20，因此缺口20，不重复扣预留。R02 缺口50、建议40、待协调10；R03 缺口50但剩余产能0，仍应保留协调候选。R04 的20吨安全目标属于明确标记的模拟批准记录。

快照不会仅改日期伪装更新。2026-11-05 的数据在 D/D-1 时效后应失效；下一轮必须复核订单未交、预留、在途和产能来源后维护快照。当前交付不是自动预测或排产优化系统。

入出库为受控 SQL 批量导入，遵循 app/services.py 的批次计价、唯一 line posting_key、库存不足/已结账期间校验和对应借贷凭证规则；并非经前台点击提交。所有新增单据 is_simulated=true，导入有审计记录，事务失败整体回滚；重复运行数据脚本不会重复过账。未安装长期提权存储过程。

## 文件执行顺序

1. supabase/ai_coordination.sql：两张来源/场景表与初始视图。
2. supabase/ai_coordination_seed.sql：场景库存、订单、BOM与来源记录（scripts/build_ai_coordination_seed.py 可重建脚本）。
3. supabase/ai_coordination_plan_documents.sql：在途订单和生产计划证据。
4. supabase/ai_coordination_dynamic_view.sql：最终动态视图。
5. supabase/ai_coordination_negative_tests.sql：拒绝与隔离验证。
6. supabase/ai_coordination_acceptance.sql：复核业务数据。
7. supabase/ai_coordination_readonly.sql：授权草案，本轮按用户要求未执行；并非重复执行脚本。

不要在已完成的生产库重复执行 DDL。数据脚本不改写已有非 SIM-AIP- 记录。日期由上海时区实际执行日确定；不能通过重新生成脚本并仅更新日期绕过来源复核。

T05 全量占用只能核查；T02/T03/T06应扣除占用后才讨论可处置量。所有候选仍为待核实建议，没有正式可销售冻结/质量货权映射。

只读权限尚未生效：自动审批先前拒绝了未确认连接角色时的持久授权，用户随后明确选择暂不授权。未创建权限组或改变原授权。admin 是 ERP 登录名，尚不能确认 ERP_READONLY_DATABASE_URL 的数据库用户名。平台维护方需提供仅用户名（无需密码/连接串），再审阅绑定和 SELECT 范围。

平台端“重新计算”、AI意见、同意/否决/待定及处理记录的操作不在当前 ERP 仓库中，本轮未声称已完成平台页面验收。由平台选择具体法人、清空搜索后读取并重算。合同 formal/framework、自然年、签署原件状态与订单合同绑定，以及库存质量/货权映射属于文档所列后续增强，本轮未冒充已完成。
