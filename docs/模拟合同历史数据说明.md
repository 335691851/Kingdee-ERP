# 模拟合同历史数据批次

批次：`contract_sim_20261104_v1`。合同编号前缀：`SIM-HT-20261104-`，序号 0001 至 1000。

这批合同是用户要求补充的合成演示数据，不是鲁盐集团真实签约、真实价格承诺或真实员工审批记录。表单、条款、PDF 和操作记录均明确标注模拟，不生成签名、公章或银行账户。

## 内容与规模

- 1,000 份合同：商品价格协议 650 份、商品与服务综合协议 250 份、服务框架协议 100 份。
- 签订日期覆盖 2025-11-05 至 2026-11-04；有效期设置 30 / 90 / 180 / 365 天，包含已到期和仍有效的场景。
- 12 家独立法人：集团总部 350 份，4 家生产法人每家 75 份，7 家营销法人每家 50 份。简称公司沿用既有主数据，不补造工商全称。
- 2,000 条客户范围关联；每份覆盖 1 至 3 个已分配客户，排除本法人自身。
- 1,800 条商品协议价格明细；仅引用对应法人的已分类销售成品。目录价为现有 ERP 模拟参数，协议价按 -8%、-5%、-3%、0%、+3%、+5% 合成变化；不能作为真实历史价格依据。
- 每份 1 个 PDF 附件。商品明细、客户、有效期、结算条件、服务条款与表单一致；不把 PDF 当作已签署文件。
- 商品单位为吨，价格单位为元/吨，金额仍按整数分保存。税率属于演示设定；运费、自提和付款条件在条款中说明。
- 服务协议不虚构按吨服务费，不混入商品价格明细；具体服务费用约定为另行确认。

模拟最终状态：已审核 720 份、已终止 90 份、已退回 90 份、待审核 50 份、草稿 50 份。审核及终止事件仅用于历史流程演示，不代表实际人员作出的审批或法律决定。

## 执行顺序

1. `supabase/contracts_history_seed.sql`：幂等插入该批次表单、客户、价格、创建记录。初始保持草稿，便于通过正常 API 上传。
2. `scripts/fill_contract_pdfs.py`：通过 ERP 正常授权接口生成、上传附件。密码交互输入，不写入代码、文件或日志；无需读取 Vercel 服务端存储密钥。需要带 ReportLab 的作者环境，不属于线上应用依赖。
3. `supabase/contracts_history_finalize.sql`：只有 1,000 份文件全部登记后才补齐模拟历史状态、事件与业务时间。
4. `supabase/contracts_history_validate.sql`：检查总数、法人范围、客户和商品授权、价格、时间、文件索引及存储对象对应关系。

表单创建与审核时间是模拟业务时间。PDF 文件实际生成及上传日为 2026-11-04；Supabase Storage 对象保留真实上传时间。统一导入账户为现有管理员，销售人员是业务责任字段，不能据此推断真实员工提交行为。

数据不会自动改变销售订单定价，不生成交易、收付款、库存、成本或总账凭证。重复执行前应先审阅批次校验结果，不覆盖用户录入的其他合同。

## 产品范围修订

合同以 contract_category 和 contract_sku 保存适用分类与 SKU，取并集；分类包含下级商品，价格明细必须属于此范围。服务框架同样必须选择范围，但不因此产生商品单价。

线上增量执行 contract_product_scope.sql、contract_product_scope_backfill.sql；商品合同沿用原价格 SKU，服务合同分类或 SKU 为明确标注的模拟设定。使用 fill_contract_pdfs.py --revision 补充产品范围版 PDF，保留旧文件。管理员可对已提交合同补充附件，状态不变且记录实际操作时间；不覆盖原签署文件。
